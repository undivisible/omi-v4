# Proactive second-brain audit

Source review of repository commit `61baf27c6321f265e506dfebd8984e79d248091f` on 2026-11-05. This is not a production, physical-device, or external-integration test. Prioritize a dependable capture-to-outcome loop before adding more channels or autonomous actions.

## Risks and gaps

1. **Raw pendant audio lifecycle.** `worker-rs/src/routes_device.rs` writes home-Wi-Fi audio into the `DEVICE_AUDIO` R2 bucket and records its key in D1. No audio consumer is visible in `worker-rs/src`; persistence is not transcription or memory. `handle_account_delete` in `worker-rs/src/glue.rs` deletes the D1 upload rows but does not delete the R2 objects. An upload can also put an object before its D1 write fails. Inspect actual bucket lifecycle and existing objects before claiming a retention or deletion guarantee. Design a durable cleanup protocol that handles orphaned objects, retries, and uploads racing account deletion; verify with an isolated bucket and database.
2. **Memory sync visibility.** `MemoryMirrorPump.pull` reports failures through a callback but returns normally; `_pullMemoryMirror` in `app/lib/app_services.dart` clears the shared notice after that return, and successful uploads clear it independently. Separate upload and download health and clear each only on its own confirmed success. Show the resulting state on mobile as well as desktop; test failure, concurrent pulls, recovery, and account changes.
3. **Proactive delivery reliability.** `worker-rs/src/digests.rs` originally inserted a review before batching its citations and delivery. A later failure left an existing review that prevented retrying those writes. The accompanying change batches the writes atomically; it does not repair reviews already left incomplete. The cron isolates per-user errors but currently discards them. Add observable retry and pending-age monitoring and investigate historical incomplete reviews without sending messages unexpectedly.
4. **Timing and prioritization.** The scheduled handler invokes digests before daily Current generation (`worker-rs/src/glue.rs`), while each scans users independently. A morning brief can therefore precede that user's new Currents. Generate eligible Currents before composing that user's brief, and align brief selection with the Current list's expiry and feedback-aware ranking. Fixed offsets and hour-wide scans also need a travel/daylight-saving strategy and a durable due-work queue before scaling beyond a single scan per window.
5. **Proactive controls.** Single-Current generation checks `proactiveRecommendations`, but the refresh and digest paths do not visibly enforce that same setting (`worker-rs/src/routes_memory/wasm_glue.rs`, `worker-rs/src/digests.rs`). Define separately whether a user permits generating suggestions and sending channel messages, including queued work, then enforce and test those semantics at each boundary.
6. **Capture and offline proof.** The local memory mirror and cloud log are substantial foundations, but physical pendant capture, reconnect/replay, and the complete meeting-to-action-to-channel loop remain release-proof work in `roadmap.md`. Home-Wi-Fi upload is not evidence of an end-to-end memory. Signed-in conversation writes also require the worker; mobile memory uses the worker-backed client. State actual offline behavior and test it under network loss and recovery.
7. **Fallback quality.** `worker-rs/src/currents_refresh.rs` can turn a cited fact into a generic action using keyword heuristics. A citation establishes provenance, not a commitment, owner, deadline, or permission. Prefer an explicitly labeled remembered fact or no action when those details are missing; evaluate suggestions against real, consented examples.

## Product direction

- **Commitment receipts:** propose a cited commitment with owner and time, and let the user confirm, correct, or reject it in their existing channel before scheduling an interruption.
- **Why now:** attach the evidence, trigger, and a correction affordance to each proactive suggestion. Explain uncertainty rather than presenting inferred intent as fact.
- **Interruption budget:** support quiet hours, channel preferences, and batching; handle explicit deadlines separately from generic morning or evening digests.
- **Outcome receipts:** report completed, failed, or approval-needed actions in the originating conversation, linked to the supporting evidence. Never imply an action succeeded merely because it was queued.
- **Cross-context synthesis:** suggest connections between a recent conversation, an open commitment, and earlier evidence only when the user can inspect each source and dismiss or correct the connection. Measure usefulness and unwanted interruptions, not just suggestion volume.

These are product hypotheses, not claims of implemented behavior. The privacy and reliability gaps above come first.
